# ОСХ-Аналитик

**ОСХ-Аналитик** (от *О*птимизация *С*остава *Х*арактеристик) — универсальная
desktop-система поддержки принятия решений для оптимизации состава
характеристик объектов. Реализация алгоритма из работы:

> Хубаев Г. Н. **Универсальный метод оптимизации состава характеристик
> объектов** // Бюллетень науки и практики. 2019. Т. 5. № 5. С. 265–275.
> [doi:10.33619/2414-2948/42/35](https://doi.org/10.33619/2414-2948/42/35)

Программа применима к любой предметной области, в которой объекты можно
описать набором (бинарных) характеристик: многофункциональные товары,
ИТ-конфигурации, услуги, требования к системам и т. п.

## Что умеет

- Загрузка матриц объектов x характеристик из **CSV** и **XLSX** в двух
  ориентациях (объекты в строках или в столбцах).
- Попарные коэффициенты сходства: **Жаккара**, **Сёренсена-Дайса**,
  **косинусный**, **включения** (асимметричный — K⊂).
- Ранжирование объектов по числу характеристик и по доминированию.
- Поиск «недостающих» характеристик — кандидатов на добавление по правилу
  Хубаева (часто встречаются у других, особенно у более «богатых»
  объектов).
- Итеративная **оптимизация состава характеристик**: удаление мало- и
  избыточно частотных признаков, оценка информационного вклада через
  норму Фробениуса разности матриц сходства, сохранение минимального
  допустимого состава.
- Экспертный анализ: матрица консенсуса, **расстояние Кемени**, **медиана
  Кемени** (точный перебор для малых n + жадная локальная оптимизация),
  **коэффициент конкордации Кендалла W**, агрегация бинарных оценок
  мажоритарным голосованием.
- Иерархическая **кластеризация** объектов и экспертов, MDS-проекция,
  дендрограмма, граф связей объектов (networkx).
- Современный desktop GUI на **PySide6** с тёмной темой и SVG-иконками.

## Архитектура

```
app/
├── modules/
│   ├── core/            алгоритмы (matrix, similarity, ranking,
│   │                    optimization, expert, clustering)
│   ├── data/            CSV/XLSX I/O, поиск demo-данных
│   └── visualization/   matplotlib + networkx, dark palette
├── ui/
│   ├── pages/           Dashboard, Matrix, Analysis, Optimization,
│   │                    Expert, Visualization
│   ├── widgets/         StatCard, DataFrameTable, Placeholder
│   ├── sidebar.py       левая навигация с иконками
│   ├── main_window.py
│   ├── state.py         AppState — единая шина состояния
│   └── app.py           QApplication, dark.qss
└── resources/
    ├── styles/dark.qss
    └── icons/*.svg, osh-analitik.ico
```

Все вычисления — чистые numpy/pandas/scipy, без привязки к GUI: модули
`app/modules` можно использовать как библиотеку.

## Получить готовую сборку

Сборка под Windows автоматически выпускается GitHub Actions. Чтобы
получить рабочий exe:

1. Открыть вкладку **Actions** репозитория.
2. Выбрать последний успешный запуск workflow `build`.
3. Скачать артефакт `OSH-Analitik-<version>-windows-x64` (внутри ZIP +
   контрольная сумма SHA256).
4. Распаковать и запустить `OSH-Analitik.exe`. Рядом будет папка
   `samples/` с демонстрационными CSV-файлами и копия `README.md`.

При теге вида `vX.Y.Z` тот же ZIP и SHA256 автоматически прикрепляются к
GitHub Release.

## Запуск из исходников

Требуется Python 3.12 на Windows.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m app
```

На Linux/macOS аналогично (но сборка релизного exe заточена под Windows).

## Демонстрационные данные

В каталоге `samples/`:

- `laptops.csv` — 10 ноутбуков x 11 характеристик (бинарная матрица).
- `experts_rankings.csv` — 5 экспертов x 6 объектов (ранги).

Кнопки **«Открыть пример…»** на страницах *Матрица объектов* и *Эксперты*
автоматически находят эти файлы рядом с exe или в каталоге проекта.

## Тесты

```powershell
pytest -q
```

Тесты покрывают ядро алгоритмов (сходство, ранжирование, оптимизация,
Кемени/Кендалл, кластеризация), I/O CSV/XLSX и краевые случаи (пустые,
полностью заполненные, идентичные строки, один объект). Конфигурация
вынесена в `pyproject.toml`, `conftest.py` выставляет offscreen-режим Qt.

## CI / Сборка

`.github/workflows/build.yml` поднимает три последовательных job на
`windows-latest`:

1. **lint** — `ruff check` + `ruff format --check`.
2. **test** — `pytest` под Python 3.12 в offscreen-режиме, выгружает
   JUnit-отчёт артефактом.
3. **build** — `pyinstaller --clean --noconfirm sysan.spec`, копирование
   `samples/` и `README.md` рядом с exe, дымовой запуск через переменную
   `SYSAN_SMOKE_EXIT_MS` (приложение корректно завершается через 3.5 c),
   упаковка в ZIP, расчёт SHA256, выгрузка артефакта и (на теге)
   прикрепление к Release.

Параметры запуска:

- `git push` в `main`/`master` или PR → линт + тесты + сборка артефакта.
- `git tag vX.Y.Z && git push --tags` → дополнительно публикация Release.
- `workflow_dispatch` с `run_release=true` → черновой ночной релиз.

## Формат входных данных

CSV/XLSX, первая колонка — имена объектов (или характеристик при
обратной ориентации), остальные ячейки — `0`/`1` либо понятные значения
(`да`/`нет`, `true`/`false`, `+`/`-`, числовые с порогом).

Для экспертного анализа — отдельный CSV/XLSX: строки — эксперты,
столбцы — объекты, значения — ранги (1 = лучший).
